Carriot

One chariot, many horses. See which of your agent sessions is working, which is planning, and which is waiting on you. Jump to that session with one keystroke, and read its plan or PR before you approve it. It works with wezterm + tmux as you use them today.

The core idea

Every session is in exactly one state

Claude Code runs a small script, called a hook, at each point in a session's life: a prompt you submit, a tool call, a permission prompt, the end of a turn. Each hook records the session's current state in a local SQLite file. Everything else on this page reads that file. States are grouped by what they ask of you:

Needs you

A permission prompt, a question, a plan waiting for approval, or a PR waiting for approval. The agent can't continue until you act.

Your turn

The agent finished its turn. Often it ends with “shall I commit?”, and that last line is shown as the detail.

Planning

Working while in plan mode. It will produce a plan you can read in carriot.

Working

Executing: editing files, running commands, implementing a plan. You can ignore it.

Proposed workflow

A morning with six sessions open

09:02
You start sessions the way you do now.

/carriot:new for a ticket, a review session, and so on. Nothing changes. The hooks are installed in carriot's project settings, so every session there is tracked automatically.

09:15
Your tmux status bar shows a coloured dot next to every window.

From any window you can see that auth-refactor is red, helm-rightsize is amber, and the rest are green. You no longer cycle through windows to find out.

09:16
Press prefix b to jump to whoever has waited longest.

This is the most-used action. It goes to the blocked session that has waited longest, then the oldest “your turn”. Answer it, press prefix b again, and repeat until nothing is waiting.

09:30
A plan arrives. Press prefix F for the overview popup.

The popup lists every session with a preview of the highlighted one. A plan is shown as formatted markdown. Press ctrl-p to read the full plan, then enter to go to that session and approve it.

10:40
An agent tries to open a PR, and carriot holds it.

When the agent runs gh pr create, carriot records the title, description, commits and full diff, then makes Claude Code ask for confirmation. Review the PR in the popup (ctrl-r) or as a GitHub-style page in the web dashboard, then approve or reject it in the terminal.

11:00
Stepping away? Keep the web dashboard open in a browser window.

It updates live, sends a desktop notification when a session needs you, and lets you reply to an agent without switching to its terminal.

Three terminal surfaces: status bar, popup and control tower

Background sessions

Close the window, keep the agent

A session doesn't need a window in your tmux sessions to keep running. Carriot keeps tracking it and reconnects you when you jump to it.

Park it

prefix P, p in the tower, or carriot park. The window moves into a hidden carriot-parked tmux session and shows as ⏸ parked. If the agent shares its window with other panes, only the agent's pane moves. Works for any agent and lasts as long as tmux is running.

Run it in Claude's background

Start with claude --bg "…" and the session runs outside tmux entirely, shown as ◌ bg. Its terminal output is still readable in the tower through claude logs. Parking an attached background session closes only its window.

Reconnect

Jump to it as usual (enter, prefix b, the picker, or the dashboard). A parked window moves back into your current tmux session. A background session opens a new window running claude attach.

Architecture

Hooks write, everything else reads

One SQLite file is the single source of truth. Each agent has a small adapter that turns its own events into carriot's common states, so a pi agent can be added later without changing the database, tmux integration, popup or dashboard.

Design decisions

Why it's built this way

Hooks, not screen scraping

Claude Code reports exactly what is happening at each point, including the plan text and the final reply. Parsing the terminal would break whenever the interface changes. The built-in claude agents list only reports idle or busy.

SQLite as the contract

Several writers (every session's hooks) and several readers (tmux, the popup, the web page, a future Mac app). WAL mode handles that concurrency, it needs no daemon, and you can query it directly with sqlite3.

Agent-agnostic from day one

Adapters convert each agent's events into one shared event type. A pi agent gets an adapter, or calls carriot emit --agent pi --state waiting from its extension hooks.

Never slows the agent

Every hook runs in the background except the PR check, which has to block. That one has a bash fast path, so Bash calls that aren't gh pr create exit in about 19ms without starting Bun. Hook errors go to a log file and never break the session.

tmux pane is the address

Each session is stored with its $TMUX_PANE, which makes jumping exact. When a pane disappears, the session is marked ended, which also cleans up after crashes.

Locked-down local web

The dashboard can type into your agents, so it binds to localhost only, checks the Host header (to block DNS rebinding), and requires a token that changes each run (to block cross-site requests). Without these, any website could send keystrokes to an agent.

Setup

Three pieces to switch it on

1. Hooks in carriot/.claude/settings.json. Running sessions pick them up automatically.

"hooks": {
  "SessionStart":      [{ "hooks": [{ "type": "command", "command": "\"$CLAUDE_PROJECT_DIR\"/bin/carriot hook claude", "async": true }] }],
  "UserPromptSubmit":  [{ "hooks": [{ … same, async … }] }],
  "PreToolUse": [
    { "matcher": "ExitPlanMode|AskUserQuestion", "hooks": [{ … same, async … }] },
    { "matcher": "Bash", "hooks": [{ "type": "command", "command": "\"$CLAUDE_PROJECT_DIR\"/bin/carriot hook-pr-gate claude" }] }
  ],
  "PermissionRequest": [{ "hooks": [{ … async … }] }],
  "PostToolUse":       [{ "hooks": [{ … async … }] }],
  "Notification":      [{ "hooks": [{ … async … }] }],
  "Stop":              [{ "hooks": [{ … async … }] }],
  "SessionEnd":        [{ "hooks": [{ … }] }]
}

2. tmux: one line at the end of ~/.tmux.conf. carriot.tmux appends the dot to your existing window formats and binds prefix F and prefix b. Comment the line out to turn carriot off.

source-file -q ~/carriot/tools/carriot/carriot.tmux

3. WezTerm shortcuts: carriot.wezterm.lua, loaded at the end of wezterm.lua, maps CMD keys onto the tmux bindings so you never type the prefix: ⌘⇧T new agent, ⌘B next waiting, ⌘⇧A tower, ⌘G picker, ⌘⇧P park, ⌘/ cheatsheet, ⌘⇧O dashboard.

4. Optional nicer rendering: brew install glow git-delta. Without them, plans and diffs fall back to plain colour output.
